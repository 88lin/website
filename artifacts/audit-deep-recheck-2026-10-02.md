## 此前确认并修复的问题

### 1. 预览服务可越过发布目录读取文件

用独立测试目录放置无敏感信息的标记文件后，请求 `/..%2Foutside.txt` 及 Windows 编码反斜杠变体，原服务返回 200 和发布目录以外的标记内容。原因是解码后直接拼接文件路径，没有检查最终路径边界。

修复：按发布根目录解析路径，检查解析路径和真实路径，拒绝越界、反斜杠、NUL 与双斜杠起始路径，同时阻断符号链接越界。这是本地预览服务的问题；GitHub Pages 托管静态产物，不运行该 Node 服务。

### 2. 畸形 URL 导致预览进程退出

请求 `/%`，原服务在 `decodeURIComponent` 处抛出未处理 URIError。现返回 HTTP 400，后续首页请求仍返回 200。

### 3. 目录跳转丢失查询参数

`/case/repair?utm_source=test` 原本重定向到 `/case/repair/`，丢掉查询参数。现保留全部参数，并补齐裸 `/website` 到 `/website/` 的重定向。另验证了 HEAD 无响应正文、gzip;q=0 不被压缩、Vary 正确及无效方法返回 405。

### 4. 编码后的正常案例被客户端判成缺失页

`/case/%72epair/` 原本得到案例 HTML，客户端却显示「页面不存在」和 noindex。现先安全解码路径，再识别路由；根路径与 `/website/` 均验证了编码入口、`index.html` 入口、查询参数与锚点入口的正文、元数据和返回链接一致。

### 5. 同一路由的斜杠变化留下旧返回链接

在 `/website/foo/` 的客户端缺失态中，通过 history 切到 `/website/foo`，原生返回链接会错误地解析到 `/`。原因是规范化后的 route 没变，路由上下文复用了原有 href。现在单独跟踪真实 pathname，斜杠变化也会更新链接；原生返回链接保持 `/website/`。

### 6. 开发模式重复创建平滑滚动实例

在 Vite 开发模式拦截并统计 window 的 wheel 监听，StrictMode 初始化后原本有两套 Lenis 监听。第一次 effect 已清理，但异步 import 完成后仍创建了实例。

现用 AbortSignal 绑定 effect 生命周期：依赖全部就绪且 effect 未清理时才创建实例，退出时移除监听与 RAF。开发模式及页面往返只保留一套监听；模拟动态依赖加载失败时不创建半初始化实例，保留原生滚动，无未处理异步异常。

## 验证范围中的缺口及调整

- 上一轮「客户端 head 一致」有些检查只等待 canonical，而 canonical 在 SSR HTML 里已经存在，不能证明客户端已启动。本轮增加启动等待，并对全部 7 条正式路由逐页比较。
- 加入 JSON-LD 节点唯一性、引用完整性和服务节点数量检查；缺少 graph 或摘要时明确失败。
- 上一轮 SPA fallback 测试替换了相对资源地址，实际代表「托管方已正确配置入口资源」的场景。直接把原始首页 HTML 返回给任意深层地址，会导致相对脚本与样式加载失败，客户端根本没有机会修正元数据。本轮明确记录此限制。
- `npm run preview` 已与 `npm run serve` 统一使用真正的静态预览服务，未知地址返回独立 HTTP 404，避免默认 Vite preview 的首页 fallback 掩盖问题。默认端口统一为 4178，允许 `PORT` 环境变量覆盖。
- 新增 `test:server`、`verify:runtime` 并接入部署工作流。
